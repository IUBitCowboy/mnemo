# Session Close

At the end of every generation session — or whenever the instructor asks what to
do next — produce a **Session Close** block. Do this proactively after completing
any artifact, without waiting to be asked. The Session Close hooks the current
session to the next.

## Format

### [Period N] Checklist — Updated
A table of all artifacts in scope for the current [period/week], marked ✓ Done
or → next.

### Recommendation
One paragraph: whether to continue in this session or start a fresh one, and why.
The usual reason to start fresh is that the next artifact type requires a different
artifact layer (e.g., switching from slides to exercises) or requires loading
completed artifacts from this session as context.

### Load Order for Next Session
A numbered table: file path (or stem), reason for including it.
Always list in the order files should be added to the chat tool context.
Follow the Generation Order Convention: lectures before exercises; completed
artifacts from the prior session before the artifacts that depend on them.

### Generation Order Within Next Session
A numbered list of artifacts to produce, in dependency order.
Note which artifacts must precede others (e.g., exercise before its paired
reflection assignment).

## When to produce it
- After completing the final artifact in a session
- When the instructor asks "what's next" or "what should I work on"
- When context is running long and a fresh session would be cleaner
- Proactively if you detect the session has drifted far from its original load order

## HIL Awareness

The Session Close is generated as part of the session transcript, not as a
student-facing artifact. However, if the Session Close references specific
artifacts that were produced, those artifacts should have HIL galley markup.
The Session Close itself does not require HIL tracking — it is a process aid,
not a deliverable.

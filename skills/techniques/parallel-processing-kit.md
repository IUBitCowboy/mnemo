# Parallel Processing Kit (4 Roles)

Define these four roles at the top of every team-based exercise. Assign setup
tasks concurrently. Adapt descriptions to the specific exercise context.

| Role | Domain | Default Responsibility |
|---|---|---|
| **Repo Admin** | Repository hygiene | Branch creation, PR setup, merge management |
| **Process Lead** | Coordination + documentation | Runs the sync callouts, owns `CONTRIBUTIONS.md`, tracks the Definition of Done |
| **Dev Lead** | Primary implementation | Core coding/configuration task for this exercise |
| **QA Sentinel** | Quality + CI/CD | Tests, linting, pipeline monitoring, runs Code Review Checklist before approving PR |

## Team Size Adaptation

*On 5-person teams: the Dev Lead role pairs two people.*

*On 3-person teams: collapse **Repo Admin + Process Lead** into a single **Ops
Lead** role by default. This keeps Dev Lead and QA Sentinel separate, preserving
code review integrity. Alternative collapse — **Process Lead + QA Sentinel** — is
permitted when the exercise has minimal repo work and QA is reviewing only one
Dev Lead's output. Never collapse Dev Lead with QA Sentinel. State the chosen
pair explicitly in the exercise instructions.*

## Role Rotation Policy

*Course policy: no student may hold the same role more than two consecutive
[periods/weeks].*

## Attendance Pre-Flight

Include at the top of every team-based exercise:

Before assigning roles, the Process Lead confirms attendance. If fewer than 3
members are present (in-person or approved remote), notify the TA immediately and
follow the [course-specific attendance policy]. Remote participation requires a
documented email request to the instructor with the team CC'd — a verbal request
is not sufficient.

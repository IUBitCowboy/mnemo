# ICEX CONVENTIONS (C291)

Apply in addition to your base persona and Mnemo skills.

## ICEX Format for C291

- **Time Limit:** 20–30 minutes in-class (within the 60/40 lecture/ICEX
  split)
- **AI Policy:** ICEX are AI-free throughout the entire semester. No AI
  tools may be used during any ICEX. This is enforced by the in-class
  setting.
- **AI Use Disclosure:** Include an `## AI Use Policy` field in every
  generated ICEX stating: "AI-free: no AI tools permitted."

## ICEX Types

C291 FA26 uses multiple ICEX types. Each generated ICEX must identify
its type.

### Standard ICEX

The default format: students write a small program illustrating the
lecture concept. The Bugsmith (Ollama agent) is available in-class for
Socratic debugging help — the Bugsmith never fixes code, it guides
through Smith's Method (Reproduce → Observe → Isolate → Hypothesize →
Test → Fix).

- **Structure:** [Task] → Theory/Experiment table → [Submission]
- The Bugsmith is referenced as a resource, not embedded in the ICEX.

### Gate ICEX

An AI-free in-class exercise that demonstrates independent hand
competency in a construct family (control flow, functions, arrays,
pointers, dynamic memory, structs, bitwise). A gate ICEX must:
- Exercise the construct in isolation, not as a side effect of a larger
  task
- Be small enough to complete in 20–30 minutes
- Have a clear pass/fail signal (compiles + passes tests + memory
  clean per ASan/valgrind)

Passing a gate ICEX is a prerequisite for the gate ceremony that
unlocks AI delegation of that construct.

### Gate Ceremony

A 3-step exercise that transitions a construct from hand-only to
delegable:

1. **Hand artifact** — the student's gate ICEX result (already
   completed)
2. **Agent generation ×2** — the instructor runs the same specification
   through an agent twice, producing two solutions from the same
   prompt. Both are provided to the student.
3. **Critique** — the student evaluates all three artifacts (their own
   + two agent versions) against the audit rubric using a critique
   worksheet.

**Critique worksheet fields:**

| Criterion | My version | Agent A | Agent B | Notes |
|---|---|---|---|---|
| Compiles clean `-Wall -Wextra` | | | | |
| Passes implied tests | | | | |
| Boundary handling | | | | |
| Memory correctness (ASan/valgrind) | | | | |
| Readability & maintainability | | | | |

Plus: *Which version would you ship to production, and why?*

The ceremony is graded on the critique worksheet, not on whose code
"wins." The learning is in the comparison, not the verdict.

### Buggy-Code Drill

Used in Week 9 and for WEVL take-home exercises. Students receive buggy
C code (generated by the Bug Forge or instructor-provided) with a clear
expected behavior. They must:
1. Debug independently (or with the Bugsmith after 3 failed attempts)
2. Submit: buggy code + corrected code + process writeup

The process writeup follows: evidence → hypothesis → test → fix. The
writeup — not the fix — is the primary assessment artifact.

### Audit Lab

Used in the auditor phase (Week 14). Students receive agent-generated
code (e.g., the HTTP server) and must:
1. Find and exploit a vulnerability (e.g., buffer overflow)
2. Produce sanitizer evidence (ASan/valgrind output)
3. Repair the code and document the fix

## Theory/Experiment Table

Every standard ICEX and gate ICEX must include a "Theory/Experiment"
table for the Theory-Driven Debugging pillar:

```
| Theory (Hypothesis) | Experiment (Test) | Result | Modified Theory |
|---|---|---|---|
| [What I think is wrong] | [What I'll try] | [What happened] | [Updated understanding] |
```

This table is the C291-specific implementation of the scientific
debugging loop. Students must fill it in during the exercise.

## WEVL (Weekly Evaluation)

Take-home debugging exercises using the Bug Forge:

- 3–6 problems per week from instructor-selected topics tied to the
  lecture
- Submit per problem: buggy code + corrected code with inline comments
  + architectural explanation paragraph
- Bug Forge auto-grades fix correctness (Y/N); hand-grade for comments
  and explanation
- Explanation prompt: *"Explain what this program does and why your fix
  works, as if explaining to a junior colleague who hasn't seen this
  code."*
- WEVL01 (Week 1) is an initial assessment — credit for completion
  only, no grading. Used to gauge incoming student debugging ability.

## AI Use Disclosure Field

Every generated ICEX must include:

```markdown
## AI Use Policy
AI-free: no AI tools permitted during this exercise.
```

For WEVL take-home exercises:

```markdown

AI tools may be used. Record tool name and model used in your
submission:
**Tool used:** [Bug Forge / Bugsmith]
**Model used:** [gemma4:cloud / etc.]
```
